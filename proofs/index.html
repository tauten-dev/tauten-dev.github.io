Proofs

Proved means a Lean theorem about the Charon/Aeneas translation of the crate that ships, checked by the five steps below.

tauten's own decisions (tiers, severity, exceptions, the baseline ratchet, the effects verdict) live in the no_std crate tauten-check-kernel and are proved this way. cargo tauten init --proofs sets up the same gate for your kernel crates.

The gate

  1. Extract. Charon and Aeneas translate the kernel crate to Lean.
  2. Drift. The translation must match the committed proofs/Extracted/.
  3. Build. lake build checks every proof.
  4. Audit. Audit.lean: axioms only propext, Classical.choice, Quot.sound; every extracted function is covered by a claim.
  5. Mutants. Each deliberately broken copy of the Rust must fail its named theorems.

Lean module only

A Lean project that already builds against Aeneas can reuse Tauten.Machine (reachability, invariants, worlds and discharge for step machines) without the CLI or any Rust crate. Vendor the file at a pinned commit (tauten 0.2.0) with its license, and commit a checksum file for both. Fetching happens once, when the pin changes; the proof build needs no network.

docs/ADOPTING.md

104$ TAUTEN=370e7050f2adaba1e0a1c7351ab686d5f1238c47   # tauten 0.2.0105$ RAW=https://raw.githubusercontent.com/tauten-dev/tauten/$TAUTEN106$ curl -fsSLo Proofs/TautenMachine.lean $RAW/crates/cargo-tauten/templates/proofs/Proofs/TautenMachine.lean107$ curl -fsSLo Proofs/TautenMachine.LICENSE $RAW/LICENSE108$ sha256sum -c TAUTEN.sha256109Proofs/TautenMachine.lean: OK110Proofs/TautenMachine.LICENSE: OK

11673a648f123876f2c3ae43610ddeac683061906d26b8ccc3b6cd297743bbe07f3  Proofs/TautenMachine.lean117bb23cea06c1a4f205b5f6e2d4ecc5ff1c1ebf15829706f1fe366424d0919e9be  Proofs/TautenMachine.LICENSE

The module imports Aeneas and nothing else: Lean v4.35.0 with the Aeneas Lean library, as in the public proofs image. Keep the project's own gate and axiom audit unchanged; tauten's gate audits the same file, proofs/Tauten/Machine.lean, to Lean's three standard axioms (the build compares the two). Change the pin and the checksums together, in one reviewed change.

The build checks that the pin is a commit of tauten 0.2.0 on the pinned history and that each checksum is the sha256 of the downloaded file at that commit.

Not proved, and trusted

Source scanning, diagnostic mapping, the rustc wrapper, workspace loading and the CLI are tested, not proved; so is the authority check (TAU-A002). Charon, Aeneas, Lean and the steps around them are trusted: proofs/TRUST.md.
