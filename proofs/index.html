Proof tier

Proofs over the shipped Rust

●Exercised (local)

The code that decides whether your build passes (tier rules, severity, exceptions, the baseline ratchet and rule-table validation) lives in a small no_std crate, tauten-check-kernel. Charon and Aeneas translate that exact crate to Lean, and the theorems below are proved about the translation. A CI workflow re-runs the whole gate whenever the kernel, the macros or the proofs change.

The gate

  1. 1 · extractCharon and Aeneas translate the kernel crate to Lean.
  2. 2 · driftThe extraction must match the committed proofs/Extracted/.
  3. 3 · buildlake build checks every proof.
  4. 4 · auditAudit.lean: axioms only propext, Classical.choice, Quot.sound; every extracted function covered by a claim.
  5. 5 · mutantsEach deliberately broken copy of the Rust must fail its named theorems.

Not proved

Source scanning, the mapping from compiler diagnostics to rule IDs, the rustc wrapper, workspace loading and the CLI are tested, not proved. So is the authority check (TAU-A002): a proof of a wrong model would have passed, as review showed. Charon, Aeneas, Lean and the steps around them are trusted; the list is in proofs/TRUST.md.

Proofs for your kernel crates

cargo tauten init --proofs sets up the same gate for your own kernel crates, and cargo tauten proofs runs it and records one outcome per claim in proofs/claims.json. When a claim is proved and its source has not changed since, arithmetic and indexing findings (TAU-N001, TAU-P003) inside that function are reported as subsumed by the named theorem rather than as errors. Any edit makes the record stale and the findings return.

The kernel's arithmetic and indexing rules duplicate what an Aeneas proof already establishes (dry-run report). P5 subsumes them only for functions with a recorded, current, total proof; writfold has not adopted the claims format yet, so its 231 findings are unchanged until it does. (docs/STATUS.md, Known gaps)

Modelled on writfold

The gate generalises the one writfold uses for its own kernel, with the same pinned Lean, Aeneas and Charon versions.
