Design decisions made while building (with reasons)

  • The CLI is the rustc wrapper. One cargo check with RUSTC_WORKSPACE_WRAPPER=cargo-tauten, so each crate gets exactly its own tier's flags. cargo clippy -- flags applied flags to dependencies too.
  • Lints compile at warn level; the profile assigns severity. With deny levels, rustc fails and dependents are never checked.
  • No rustc forbid. Derive macros (clap, among others) emit #[allow(clippy::...)], which rustc rejects under forbid. "No exceptions" is a structural check instead (TAU-X004).
  • Separate profile for test targets (in_tests). Calibrated on writfold, where most panic and IO findings were legitimate test code.
  • Refined types live in a private generated module, so even the defining module cannot bypass try_new.
  • Contracts only on Result-returning functions. A violation is a returned error in every build profile; there is no release-mode disabling and no panic.
  • Baseline keyed without line numbers, and it may only shrink.
  • The build directory is keyed by a hash of the profile and tier map, because cargo does not fingerprint what a wrapper adds.

Known gaps

  • The capability rule is discipline, not confinement (see MAPPING.md).
  • The kernel's arithmetic and indexing rules duplicate what an Aeneas proof already establishes. The proof tier should subsume them; see the dry-run report.
  • S002 (placeholder comments) is a heuristic.
  • The benchmark has 4 dev tasks on one host. The plan needs about 24 across 3 hosts, with ≥ 16 held out. The dev-split pilot hit a ceiling, so harder held-out tasks are needed.
  • Contracts do not yet support async fn or generic newtypes; they have no Kani (cfg(kani)) lowering yet.
  • No measurement of agent behaviour yet. Nothing here supports a claim that agents make fewer mistakes.
