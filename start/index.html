Getting started

Install the CLI, give each crate a tier, and run the check.

Install

cargo-tauten is a Cargo subcommand and brings its own profile. The library API is on docs.rs.

$cargo install --locked cargo-tauten

Then run cargo tauten check in your workspace. Needs Rust 1.98 or newer, with clippy.

Declare tiers

Each crate declares a tier. kernel is pure and can be proved, core takes its effects as parameters, edge is the only place that touches the world.

Cargo.toml

25[package.metadata.tauten]26tier = "core"   # "kernel" | "core" | "edge"
From the tauten README.
TierMeaningExamples of what is rejected
kernelPure, no_std, deterministic decisions; eligible for proofsany exception to a profile rule, floats, HashMap, Rc/RefCell, outward dependencies
coreLibrary code; effects arrive as parametersstd::fs::read, SystemTime::now, println!, detached threads, globals, unwrap, indexing, unchecked +
edgeStartup and IO; the only tier that may create authorityunwrap, ignored results, stubs (most other rules become warnings)

Dependencies point inward only: edge → core → kernel (TAU-T002). cargo tauten init proposes a tier for each crate that has none; --write applies it.

Check

Run cargo tauten check on every edit. Error-level findings exit with code 1. The CLI owns the profile, so loosening your own clippy.toml or [lints] does not weaken it. --format json prints one diagnostic per line, the form an agent should read.

README.md

38$ cargo tauten check                 # human output39$ cargo tauten check --format json   # one diagnostic per line, stable schema40$ cargo tauten explain TAU-A001      # why the rule exists and how to fix it

$ cargo tauten check

error[TAU-P001]: used `unwrap()` on a `Result` value  --> rej-unwrap/src/lib.rs:6:5 (core crate `rej-unwrap`)  = rule: No unwrap/expect on fallible values (decided by Clippy)  = fix: Propagate with `?` and a typed error, or handle the None/Err case explicitly with match, if let, or a default chosen on purpose.

To excuse one item, put #[expect(lint, reason = "...")] on it. #[allow] is itself a finding (TAU-X001), and some rules admit no exception.

Adopt gradually

cargo tauten baseline records today's findings. Later checks report only new ones. The baseline may only shrink.

$ cargo tauten check

error[TAU-P001]: used `unwrap()` on a `Result` value  --> crates/parse/src/lib.rs:12:5 (core crate `parse`)  = rule: No unwrap/expect on fallible values (decided by Clippy)  = fix: Propagate with `?` and a typed error, or handle the None/Err case explicitly with match, if let, or a default chosen on purpose. warnings (run with --warnings to list them):       2  TAU-D001  Documented public APItauten: 1 error(s), 2 warning(s), 2 accepted by the baseline

A new unwrap after the baseline was recorded: it is an error, and the recorded findings are accepted. Recording more findings needs --allow-increase.

Prove a kernel function

cargo tauten init --proofs <crate> --write sets up the gate. cargo tauten proofs runs it and records one outcome per claim. Without Docker or the image nothing is checked and nothing passes. What counts as proved: Proofs.

README.md

78$ cargo tauten init --proofs my-kernel --write   # writes proofs/ (claims.toml, gate, Lean project)79$ sh proofs/refresh.sh                           # translate the crate (Docker, pinned image)80$ cargo tauten proofs                            # run the gate; one JSON outcome per claim

Tell the agent

cargo tauten init --write adds AGENTS.tauten.md. Point your AGENTS.md or CLAUDE.md at it.

AGENTS.tauten.md (first paragraph)

This workspace uses the tauten profile. `cargo tauten check` must pass beforeyou report a task as done. Run it with `--format json` to get one diagnosticper line; each has a rule `id`, the `file`/`line`, and a `fix`.`cargo tauten explain <ID>` prints the full rule.

Commands

Parsed from crates/cargo-tauten/src/main.rs

cargo tauten check
    Run structural checks and clippy with the profile for each crate's tier
cargo tauten baseline
    Record current error-level findings as the baseline (the ratchet)
cargo tauten init
    Propose a tier for every crate without one and write the agent profile; with --proofs <crate>, set up the proof tier for a kernel crate instead
cargo tauten proofs
    Run the project's proof gate (proofs/claims.toml) and print one JSON outcome per claim: proved, drift, build-failed, audit-failed, mutant-survived or tool-missing
cargo tauten explain
    Explain a rule, e.g. cargo tauten explain TAU-P001; without an ID, list all rules
cargo tauten profile
    Print the generated clippy flags and clippy.toml for a tier

cargo tauten explain <ID> prints any rule; they are all on Rules.
