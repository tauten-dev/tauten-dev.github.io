Getting started

Getting started

Install the CLI, declare a tier per crate, check on every edit, adopt gradually with a baseline, and prove kernel functions. Every output below was captured at 8fb6ade.

  1. Install

    cargo-tauten is a Cargo subcommand. Install it once; it brings its own profile, so there is nothing to configure in your project.

    The library API (tauten::cap, #[refined], contracts) is documented on docs.rs.

    $cargo install --locked cargo-tauten

    Needs Rust 1.98 or newer, with clippy.

  2. Declare tiers

    Every crate declares a tier in its manifest. cargo tauten init proposes one for each crate that has none and prints the plan; --write applies it.

    • a no_std library is proposed as kernel: pure decisions, eligible for proofs;
    • a library as core: effects arrive as parameters;
    • a binary-only crate as edge: the only tier that may create authority.

    With --write it also writes AGENTS.tauten.md, the agent profile.

    Cargo.tomlFrom the repo
    [package.metadata.tauten]tier = "core"   # "kernel" | "core" | "edge"
    $ cargo tauten initCaptured
    rules                        tier = "kernel"   (no_std library; crates/rules/Cargo.toml)ledger                       tier = "core"   (library; crates/ledger/Cargo.toml)cli                          tier = "edge"   (binary only; crates/cli/Cargo.toml)AGENTS.tauten.md             agent instructions Nothing written. Re-run with --write to apply; change any tier afterwards by hand.

  3. Check, on every edit

    cargo tauten check runs clippy and the structural checks with each crate's own tier. Error-level findings fail the run with exit code 1. The CLI owns the profile: deleting or loosening a project's own clippy.toml or [lints] table does not weaken the check.

    --format json prints one diagnostic per line, the form an agent should read. cargo tauten explain <ID> prints a rule.

  4. Adopt gradually

    cargo tauten baseline records today's error-level findings in tauten-baseline.json. Later checks accept up to that many per rule and file, and report anything new.

    The baseline may only shrink. A slot that is no longer needed is itself an error (TAU-R001), and recording more findings is refused without --allow-increase.

  5. Prove kernel functions

    cargo tauten init --proofs <kernel crate> --write sets up the proof gate for a kernel crate: proofs/claims.toml, the Lean project and the gate scripts. cargo tauten proofs runs it in the pinned image and records one outcome per claim. A fresh, proved, total claim discharges the arithmetic and indexing findings inside that function.

    Planned (0.1) cargo tauten ship at the end of a feature re-runs only the proofs of stale claims; verify --level full runs everything nightly. The cadence.

    Proof tierFrom the repo
    cargo tauten init --proofs my-kernel --writesh proofs/refresh.sh

  6. Tell the agent

    Point your AGENTS.md or CLAUDE.md at AGENTS.tauten.md. It tells the agent that cargo tauten check must pass before it reports a task as done, and how to fix a finding instead of hiding it.

    The whole profile

    Reproduced from crates/tauten-check/agents.md at 8fb6ade.

    Strictness profile (tauten)

    This workspace uses the tauten profile. cargo tauten check must pass before you report a task as done. Run it with --format json to get one diagnostic per line; each has a rule id, the file/line, and a fix. cargo tauten explain <ID> prints the full rule.

    Tiers. Every crate declares [package.metadata.tauten] tier: - kernel: pure decisions. no_std, no IO, no floats, no HashMap, no shared mutability, no lint exceptions at all. - core: library logic. No direct filesystem, environment, process, clock, randomness, network, stdout/stderr or global state. These arrive as parameters (a capability, a &mut impl Write, a Clock trait). - edge: main, startup, adapters. The only place that touches the world or creates capabilities. Keep it thin.

    Dependencies point inward only: edge → core → kernel.

    When a rule fires, fix the cause. - Do not add #[allow]. If an exception is truly correct, use #[expect(lint, reason = "why this is safe here")] on the smallest item, and say so in your report. Some rules (stubs, unsafe outside the edge, anything in a kernel crate) admit no exceptions. - Do not move code to the edge tier, change a crate's tier, or edit [lints]/clippy.toml to make a finding go away. - Replace unwrap/expect with ? and a typed error enum. - Replace a + b with checked_add (or saturating_* when that is the specified behaviour), v[i] with .get(i), as with try_from. - List every enum variant instead of _ =>. - Never leave todo!(), unimplemented!(), dbg!() or "for now" comments.

    Tests. Tests may panic, index, do arithmetic, use temp files and print. They may not silently drop a Result, use stubs, or use #[allow]. Put helpers used only by tests inside #[cfg(test)] modules. Never delete, weaken or #[ignore] a test to make a task pass; report the conflict instead.

  7. Exceptions

    When a finding is wrong for one item, excuse it there: #[expect(lint, reason = "...")] on the smallest item. #[allow] is itself a finding (TAU-X001), and so is a crate-wide exception (TAU-X002).

    Some rules admit none: stubs, unsafe outside the edge, and anything in a kernel crate (TAU-X004).

    $ cargo tauten checkCaptured
    error[TAU-X004]: exception for `clippy::todo` (TAU-S001) is not permitted in edge crates  --> rej-stub-excused/src/lib.rs:4:1 (edge crate `rej-stub-excused`)  = rule: No exceptions to this rule here (enforced by Tauten)  = fix: Remove the `#[expect]`/`#[allow]` and fix the code it excused.
