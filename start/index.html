Getting started

Getting started

Install the CLI, declare a tier per crate, check, and adopt gradually with a baseline. Every output below was captured at bbb20eb.

  1. Install

    cargo-tauten is a Cargo subcommand. Install it once; it brings its own profile, so there is nothing to configure in your project.

    $cargo install --locked cargo-tauten

    Needs Rust 1.98 or newer, with clippy.

  2. Declare tiers

    Every crate declares a tier in its manifest. cargo tauten init proposes one for each crate that has none and prints the plan; --write applies it.

    • a no_std library is proposed as kernel;
    • a library as core;
    • a binary-only crate as edge.

    With --write it also writes AGENTS.tauten.md, the agent profile. Review the proposals: a library that does IO directly belongs at the edge, or should be split.

    Cargo.tomlFrom the repo
    [package.metadata.tauten]tier = "core"   # "kernel" | "core" | "edge"
    $ cargo tauten initCaptured
    rules                        tier = "kernel"   (no_std library; crates/rules/Cargo.toml)ledger                       tier = "core"   (library; crates/ledger/Cargo.toml)cli                          tier = "edge"   (binary only; crates/cli/Cargo.toml)AGENTS.tauten.md             agent instructions Nothing written. Re-run with --write to apply; change any tier afterwards by hand.

  3. Check

    cargo tauten check runs clippy and the structural checks with each crate's own tier. Error-level findings fail the run with exit code 1.

    Add --format json for one diagnostic per line, the form an agent should read. --warnings lists each warning instead of a per-rule summary.

    $ cargo tauten checkCaptured
    error[TAU-P001]: used `unwrap()` on a `Result` value  --> rej-unwrap/src/lib.rs:6:5 (core crate `rej-unwrap`)  = rule: No unwrap/expect on fallible values (enforced by Clippy)  = fix: Propagate with `?` and a typed error, or handle the None/Err case explicitly with match, if let, or a default chosen on purpose. warnings (run with --warnings to list them):       3  TAU-D001  Documented public API       1  TAU-S002  Suspicious placeholder comments       1  clippy::match_like_matches_macro  tauten: 36 error(s), 5 warning(s)

    One block and the summary line, from a run over the tauten fixture crates.

    $ cargo tauten check --format jsonCaptured
    {  "id": "TAU-P001",  "severity": "error",  "crate": "rej-unwrap",  "tier": "core",  "file": "rej-unwrap/src/lib.rs",  "line": 6,  "column": 5,  "message": "used `unwrap()` on a `Result` value",  "rule": "No unwrap/expect on fallible values",  "why": "unwrap/expect turn every unexpected input into a crash, and agents use them to silence the type checker instead of handling the case.",  "fix": "Propagate with `?` and a typed error, or handle the None/Err case explicitly with match, if let, or a default chosen on purpose.",  "enforced_by": "clippy",  "source": "clippy::unwrap_used"}

    The same finding as JSON, pretty-printed for reading; the CLI prints it on one line.

  4. The profile is the CLI's

    The CLI owns the profile: it runs one cargo check with itself as the workspace rustc wrapper, adding each crate's tier lints and a generated clippy configuration. Deleting or loosening a project's own clippy.toml or [lints] table does not weaken the check.

    cargo tauten explain <ID> prints a rule: why, the fix, the level per tier, and the lints behind it.

    $ cargo tauten explain TAU-P001Captured
    TAU-P001: No unwrap/expect on fallible values Why: unwrap/expect turn every unexpected input into a crash, and agents use them to silence the type checker instead of handling the case. Fix: Propagate with `?` and a typed error, or handle the None/Err case explicitly with match, if let, or a default chosen on purpose. Enforced by: ClippyApplies to tests: noExceptions allowed: with #[expect(.., reason)]  kernel deny  core deny  edge denyLints: clippy::unwrap_used, clippy::expect_used, clippy::get_unwrap

  5. Adopt gradually

    cargo tauten baseline records today's error-level findings in tauten-baseline.json. Later checks accept up to that many per rule and file, and report anything new.

    The baseline may only shrink. A slot that is no longer needed is itself an error (TAU-R001), and recording more findings is refused without --allow-increase. The whole sequence is on the cargo-tauten page.

    $ cargo tauten baseline --output tauten-baseline.jsonCaptured
    tauten: baseline tauten-baseline.json accepts 1 finding(s)
    $ cargo tauten checkCaptured
    error[TAU-P001]: used `unwrap()` on a `Result` value  --> crates/parse/src/lib.rs:12:5 (core crate `parse`)  = rule: No unwrap/expect on fallible values (enforced by Clippy)  = fix: Propagate with `?` and a typed error, or handle the None/Err case explicitly with match, if let, or a default chosen on purpose. warnings (run with --warnings to list them):       2  TAU-D001  Documented public APItauten: 1 error(s), 2 warning(s), 1 accepted by the baseline

  6. Tell the agent

    Point your AGENTS.md or CLAUDE.md at AGENTS.tauten.md. It tells the agent that cargo tauten check must pass before it reports a task as done, and how to fix a finding instead of hiding it. Read the agent profile.

    AGENTS.tauten.md (first paragraph)From the repo
    This workspace uses the tauten profile. `cargo tauten check` must pass beforeyou report a task as done. Run it with `--format json` to get one diagnosticper line; each has a rule `id`, the `file`/`line`, and a `fix`.`cargo tauten explain <ID>` prints the full rule.

  7. Exceptions

    When a finding is wrong for one item, excuse it there: #[expect(lint, reason = "...")] on the smallest item. #[allow] is itself a finding (TAU-X001), and so is a crate-wide exception (TAU-X002).

    Some rules admit none: stubs, unsafe outside the edge, and anything in a kernel crate (TAU-X004).

    $ cargo tauten checkCaptured
    error[TAU-X004]: exception for `clippy::todo` (TAU-S001) is not permitted in edge crates  --> rej-stub-excused/src/lib.rs:4:1 (edge crate `rej-stub-excused`)  = rule: No exceptions to this rule here (enforced by Tauten)  = fix: Remove the `#[expect]`/`#[allow]` and fix the code it excused.

What each tier looks like

Dependencies point inward only: edge → core → kernel (TAU-T002).
