Benchmark

Does the profile reduce escaped defects?

Pending No real agent has been run yet; there are no results.

Question. When an AI coding agent reports a task as done, does working under the tauten profile reduce the defects that escape, and at what cost in success rate and time?

Reproduced from bench/README.md at 736c335.

Arms

Arm The agent gets
A The repo and "run cargo test"
B A plus the same rules in prose (told, not enforced)
C Tiers declared in the manifests, the tauten agent profile, and "cargo tauten check must pass"

B separates the effect of being told from the effect of being checked.

What is measured

  • Escaped defect (primary): a hidden-oracle failure on the finished repo. The oracle is black-box (it runs the binary), so it judges behaviour, never lint counts or architecture.
  • Reachable panic: the binary panicked on oracle input.
  • Test tampering: visible #[test]s removed, or #[ignore] added.
  • Stubs: todo!/unimplemented! added.
  • Profile findings: cargo tauten check is run in every arm, as a measurement.
  • Cost: agent wall time and exit status. Token usage is planned, taken from the agent's JSON output.

Harness validation with built-in agents (not a result about AI agents)

●Exercised with built-in agents only dated 2026-11-18 in bench/README.md

Three built-in agents check the harness itself before any model is paid for. reference applies the task's known-good solution, null changes nothing, and sloppy applies a hand-written plausible solution with the typical mistake. A task is admitted only when each produces what the table requires: the oracle must pass the reference and catch the other two, and the profile must name the sloppy mistake.

$ python3 -I bench/run.py --agent reference --tasks dev --out results/validate.jsonl$ python3 -I bench/run.py --agent null      --tasks dev --out results/validate.jsonl

Required before a task is admitted:

Agent Must produce
reference oracle 100%, 0 profile errors, in arms A and C
null an escaped defect
sloppy an escaped defect and at least one profile error naming the mistake

Preregistration Draft, not frozen

Reproduced from bench/PREREGISTRATION.md at 736c335.

This file is frozen by committing it, and recording its hash in the results, before any held-out run. Until then it may change.

Hypothesis

Agents working in arm C (the tauten profile enforced in their loop) leave fewer escaped defects than in arm A (plain Rust), without a large loss in task success or a large rise in cost. Arm B (rules stated, not enforced) separates instruction from enforcement.

Primary outcome

Escaped-defect rate: the share of trials whose final repo fails at least one hidden-oracle test, or whose oracle fails to build. One value per trial.

Secondary outcomes

Reported, but not used for the go/no-go: - reachable-panic rate; - visible tests pass; - test tampering; - stubs added; - profile errors in the final repo; - agent wall time; - token usage, once captured.

Design

Item Setting
Tasks Dev split (currently 4): used for tuning the profile and harness. Held-out split (≥ 16, not yet written): oracles written and hashed before the profile is frozen for the run.
Arms A, B, C, the same tasks for each
Trials ≥ 5 per task per arm for held-out; 3 for the pilot
Model One named model and version for the primary analysis. A second model as a replication, reported separately.
Isolation Fresh container per trial; same turn and time limits for every arm
Order Trials interleaved across arms to spread provider-side drift

Analysis

  • Paired by task.
  • Difference of arm means (C − A, B − A), averaged over tasks.
  • 95% bootstrap CI resampling tasks: 10,000 resamples, seed 20261118.
  • If the CI includes 0, the report says "no measured difference".
  • All trials are reported, including timeouts and crashes; a trial that produces no change counts as a defect if its oracle fails.

Go/no-go (from PLAN.md §9)

  • Stop the product claims if, after the pilot and one tuning pass, C vs A shows no reduction in escaped defects: the CI includes 0 and the point estimate is under 15% relative.
  • Cut rules if C lowers task success by more than 10 points, or raises median cost by more than 40%, without at least a 30% defect reduction.

Honesty rules for publication

  • Every number carries the model, date, n and CI.
  • Null and negative results are published.
  • Raw JSONL and transcripts are published with the harness commit.
  • No result from the dev split is presented as a held-out result.

Limits

The benchmark has 4 dev tasks on one host. The plan needs about 24 across 3 hosts, with ≥ 16 held out, and no real agent has been run.

Kill criteria

Publishing the conditions under which the project stops is part of the plan.

Reproduced from docs/PLAN.md at 736c335.

  • After M4 + one tuning pass, arm C shows no escaped-defect reduction vs A (CI includes 0 and point estimate < 15% relative): stop product + website.
  • C drops task success > 10 points or raises median tokens > 40% without ≥ 30% defect reduction: cut rules or stop.
  • M0–M4 exceeds 10 agent-days by > 50% without pilot numbers: reassess.
  • Proof tier can't be templated in 3 agent-days: ship without it.
