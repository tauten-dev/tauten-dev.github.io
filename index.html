A strictness profile for Rust · pre-release

Strict Rust for code written by agents. Every rule names what enforces it.

Agents rarely get memory safety wrong in Rust: the compiler stops them. What gets through is everything else: unwrap on input, unchecked arithmetic, todo!() left behind, errors silently dropped, library code that quietly reads the clock. tauten turns those into checked rules, sorted by how much authority a crate holds, each with a stable ID and a repair hint an agent can act on.

01 / What gets through

Six mistakes the compiler accepts

Each compiles. Each is a fixture in the tauten repository, and cargo tauten check flags it with the rule shown.

TAU-P001

Unwrap on input

unwrap/expect turn every unexpected input into a crash, and agents use them to silence the type checker instead of handling the case.

rej-unwrap/src/lib.rs
pub fn port(text: &str) -> u16 {    text.parse().unwrap()}
TAU-N001

Unchecked arithmetic

Integer overflow and division by zero either panic or wrap silently depending on build profile; both are logic errors agents rarely test.

rej-contract-overflow/src/lib.rs
pub fn next(x: u8) -> u8 {    x + 1}
TAU-S001

A stub left behind

Agents leave todo!() and unimplemented!() behind and report the task done.

rej-stub/src/lib.rs
pub fn fee(_amount: u64) -> u64 {    todo!()}
TAU-E001

A dropped error

Dropping a Result or discarding the original error is how failures go silent.

rej-ignored-result/src/lib.rs
pub fn run() {    step();}
TAU-M001

A wildcard arm

A _ arm silently absorbs variants added later; exhaustive matches turn a new variant into a compile error at every decision site.

rej-wildcard/src/lib.rs
match mode {    Mode::Write => true,    _ => false,}
TAU-A001

Reading the clock

Filesystem, network, environment, clock, randomness and process access must arrive as parameters (capabilities), so a signature shows everything a function can touch and tests can substitute them.

rej-ambient-clock/src/lib.rs
pub fn now() -> std::time::SystemTime {    std::time::SystemTime::now()}

02 / Tiers

Rules follow authority

Each crate declares how much of the world it may touch. The less it can touch, the stricter its rules.

Cargo.tomlFrom the repo
[package.metadata.tauten]tier = "core"   # "kernel" | "core" | "edge"

Dependencies point inward only: edge → core → kernel (TAU-T002).

A structural rule: authority minted in a core crate

03 / The loop

Diagnostics an agent can act on

  1. One diagnostic per line

    cargo tauten check --format json prints one JSON object per finding: the rule ID, where it is, why the rule exists, how to fix it, and what enforces it.

    Shown pretty-printed for reading; the CLI prints it on one line.

    $ cargo tauten check --format jsonCaptured
    {  "id": "TAU-P001",  "severity": "error",  "crate": "rej-unwrap",  "tier": "core",  "file": "rej-unwrap/src/lib.rs",  "line": 6,  "column": 5,  "message": "used `unwrap()` on a `Result` value",  "rule": "No unwrap/expect on fallible values",  "why": "unwrap/expect turn every unexpected input into a crash, and agents use them to silence the type checker instead of handling the case.",  "fix": "Propagate with `?` and a typed error, or handle the None/Err case explicitly with match, if let, or a default chosen on purpose.",  "enforced_by": "clippy",  "source": "clippy::unwrap_used"}

  2. The rule, on demand

    cargo tauten explain TAU-P001 prints the full rule: why, the fix, the level per tier, and the lints behind it.

    $ cargo tauten explain TAU-P001Captured
    TAU-P001: No unwrap/expect on fallible values Why: unwrap/expect turn every unexpected input into a crash, and agents use them to silence the type checker instead of handling the case. Fix: Propagate with `?` and a typed error, or handle the None/Err case explicitly with match, if let, or a default chosen on purpose. Enforced by: ClippyApplies to tests: noExceptions allowed: with #[expect(.., reason)]  kernel deny  core deny  edge denyLints: clippy::unwrap_used, clippy::expect_used, clippy::get_unwrap

  3. The profile cannot be loosened from inside the project

    The CLI owns the profile: it runs one cargo check with itself as the workspace rustc wrapper, adding each crate's tier lints and a generated clippy configuration. Deleting or loosening a project's own clippy.toml or [lints] table does not weaken the check.

    Exceptions are possible only as #[expect(lint, reason = "...")] on the smallest item, and never for stubs, unsafe outside the edge, or anything in a kernel crate.

    Quoted from the tauten README at 736c335.

04 / Enforced, and not

What is enforced, and what is not

Enforced

  • rustc: 3 rules. Never ignore a result, No unsafe outside the edge, Documented public API
  • Clippy, at levels the profile sets: 25 rules. No unwrap/expect on fallible values, No explicit panics, No panicking index or slice, No panics inside fallible functions …
  • tauten structural checks: 9 rules. Suspicious placeholder comments, No crate-wide exceptions to profile lints, Manifest lint table loosens the profile, No exceptions to this rule here …
  • 11 rules admit no exception; in kernel crates, none do (TAU-X004).

Not enforced

  • Capability discipline, not containment. Dependencies, unsafe, FFI and build scripts keep ambient access.
  • Panic rules are syntactic. Panics inside dependencies and allocation failure are not covered.
  • Contracts and refinements are runtime checks. Nothing is proved statically yet.
  • Rust cannot express per-function effect rows; tiers are a coarse stand-in.
  • An agent can still add .clone() to quiet the borrow checker, or a reasoned #[expect] (visible in review).
  • Async cancellation safety is not enforceable.
  • The placeholder-comment rule (TAU-S002) is a heuristic.
  • No measurement of agent behaviour yet. Nothing here supports a claim that agents make fewer mistakes.
