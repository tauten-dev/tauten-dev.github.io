tauten

A strict way to write Rust. Library code takes the clock, files and environment as parameters, says so in its signature, and its pure core can be proved in Lean.

Version 0.1.0 is on crates.io. Early release. No defect-reduction claim (why).

$cargo install --locked cargo-tauten

Then run cargo tauten check in your workspace. Needs Rust 1.98 or newer, with clippy.

What it does

Authority is a parameter

Core crates may not read the clock, the filesystem or the environment. They take them as arguments, and only the edge crate creates them.

Limit. Not confinement: dependencies, unsafe, FFI, build scripts and unlisted crates keep ambient access. Claim "discipline", never "sandbox". (docs/MAPPING.md)

Effects are in the signature

#[effects(..)] states what a function may do. The check compares it with the parameters and return type. Here a read-only directory cannot grant fs_write, and the crate sets effects = "required", so the mismatch is an error. New in 0.1.0.

Limit. Parameter types are classified by name, and the effects of called functions are not seen (TAU-F001).

A proof replaces a finding

In a kernel crate, a function proved in Lean never to fail has its arithmetic and indexing findings reported as subsumed. Without such a proof they stay errors.

double stays an error. Its claim's outcome is audit-failed: “Proofs.SubKernel.double_spec does not state that sub_kernel.double never fails for every input.”

Limit. tauten trusts the project's gate output, including its total-shape check; it does not re-check the Lean theorems itself. (docs/STATUS.md, Known gaps)

What it does not do

  • It is a discipline for the code you write. Dependencies, unsafe and FFI keep ambient access.
  • Only the listed theorems are proved. Charon, Aeneas and Lean are trusted.
  • We measured defect reduction and did not find it. Status.
