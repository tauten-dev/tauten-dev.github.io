Discipline

The discipline

Four ideas carried into Rust, plus proofs over the code that ships. Each says what enforces it, how far it has got, and where it stops.

compiler: rustc rejects it. lint: a lint or tauten check, escapable only by a visible, reasoned #[expect]. proved: a Lean theorem over the translation of the shipped code. bounded: model-checked up to a bound; never counted as proved. convention: review only.

  1. Authority passed explicitly

    Core code takes the clock, the environment or a directory as a parameter; only the edge creates them.

    • ●Exercised tauten::cap, TAU-A001, TAU-A002 and TAU-G001, released
    • In progress a Cap marker trait, #[derive(Cap)] bundles and a read-only directory

    Enforced by

    • compiler capabilities have private constructors
    • lint ambient APIs are banned outside the edge, and only the edge may mint authority

    Gap. Not confinement: dependencies, unsafe, FFI, build scripts and unlisted crates keep ambient access. Claim "discipline", never "sandbox". (docs/MAPPING.md)

  2. Effects visible in signatures

    Capability parameters, Result and async are a function's effect row; #[effects(..)] states it and a check compares the two.

    • In progress #[effects(..)] and the signature check
    • Planned a committed effects.lock that fails when a public row widens

    Enforced by

    • compiler fail through Result, suspend through async
    • lint declared row against the signature, matched by type name
    • proved a kernel function's row is empty: its Aeneas translation is a pure Lean function

    Gap. Rust cannot express per-function effect rows: a row derived from the signature is an upper bound with known holes, such as effects carried in closures or trait objects.

    Before / afterProposed API
    // before: nothing in the signature says it reads the clock and a filepub fn renew_now(slot: usize, ttl: u64) -> Result<(), LeaseError> { ... }// after: capabilities as parameters, and the row declared#[effects(clock, fs_read, fs_write, fail)]pub fn renew_now<C: Clock>(caps: &LeaseCaps<'_, C>, slot: Slot, ttl: Ttl) -> Result<(), LeaseError> { ... }
    The after is the D0 spec's API (being built on the discipline-d0 branch); the before is an illustration.

  3. Checked evidence

    A check returns evidence that borrows what it checked, so changing the state before acting on it does not compile.

    • In progress tauten::origin::Evidence and #[evidence]

    Enforced by

    • compiler the evidence holds a borrow of the checked state
    • bounded check-then-act against files or a database is model-checked with TLC, up to a bound

    Gap. Freshness against external state cannot be typed, and once evidence is redeemed it no longer borrows the state; past that point it is convention.

  4. Refinement types

    A value with a rule is a type that can only be built through its check; in kernel crates that check is proved.

    • ●Exercised #[refined], #[newtype], #[requires] and #[ensures], released
    • Planned the provable fragment and drafted Lean statements

    Enforced by

    • compiler construction only through try_new
    • lint a provable type must stay inside a checkable predicate fragment
    • proved per type in kernel crates; today, the macro output for listed instances

    Gap. No static predicate propagation: Percent + Percent is checked again at runtime, and a predicate outside the fragment is tested, never proved.

  5. Proofs over the shipped code, on a cadence

    Kernel crates are translated to Lean with Charon and Aeneas; theorems about that translation are axiom-audited and calibrated with mutants.

    • ●Exercised tauten's own kernel, and cargo tauten proofs for yours
    • Planned (0.1) ship, verify --level and per-claim fingerprints
    • Planned TLC configurations as claims

    Enforced by

    • proved Lean theorems over the Aeneas translation of the code that ships
    • bounded TLC configurations for protocols; never counted as proved

    Gap. Only the listed theorems are proved; Charon, Aeneas and Lean are trusted, and Aeneas accepts a narrow subset of Rust, so kernel code has to be written in that shape.
