TAU-A001: No ambient authority

Why: Filesystem, network, environment, clock, randomness and process access must arrive as parameters (capabilities), so a signature shows everything a function can touch and tests can substitute them.

Fix: Take a capability parameter (for example a `&cap_std::fs::Dir` from `Authority::dir`, `&dyn tauten::cap::Clock`, or `&tauten::cap::Env`) and let an edge crate construct it.

Decided by: Clippy
Decides: No call to a banned ambient-authority API (filesystem, network, environment, clock, randomness, process) outside the edge.
Sees: resolved; complete: yes
Does not see: Code expanded from macros defined in other crates (clippy skips it); code disabled by `cfg`; build scripts. APIs not on the tier's ban list (clippy.toml), including dependency functions that wrap a banned one; foreign code.
Applies to tests: no
