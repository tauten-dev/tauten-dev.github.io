TAU-N002: No lossy `as` casts

Why: `as` silently truncates, wraps and changes sign.

Fix: Use `From`/`TryFrom` (`u32::try_from(x)?`) so out-of-range values become errors. In a kernel crate `cargo tauten obligations` lists it, but a recorded proof that the function never fails does not discharge it: an `as` cast never fails, it changes the value. Only a lossless or checked conversion does.

Decided by: Clippy
Decides: No `as` conversion that can lose information in linted code.
Sees: resolved; complete: yes
Does not see: Code expanded from macros defined in other crates (clippy skips it); code disabled by `cfg`; build scripts.
Applies to tests: no
Exceptions allowed: with #[expect(.., reason)]
  kernel deny
  core deny
  edge warn
Lints: clippy::as_conversions, clippy::cast_possible_truncation, clippy::cast_sign_loss, clippy::cast_possible_wrap
