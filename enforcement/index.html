What is enforced, and what is not

Sovel idea → Rust mechanism

This is the enforcement table the website will reproduce unedited. "Status" says what exists in this repository today; "Strength" says what does the enforcing.

Strength: C = rustc type system · L = lint or tauten check (escapable only by a visible, reasoned #[expect], and not at all where marked "no exceptions") · P = proved for kernel functions (proof tier, planned) · V = convention/review only.

Known gaps

Reproduced from docs/STATUS.md at 736c335.

  • The capability rule is discipline, not confinement (see MAPPING.md).
  • The kernel's arithmetic and indexing rules duplicate what an Aeneas proof already establishes. The proof tier should subsume them; see the dry-run report.
  • S002 (placeholder comments) is a heuristic.
  • The benchmark has 4 dev tasks on one host. The plan needs about 24 across 3 hosts, with ≥ 16 held out, and no real agent has been run.
  • Contracts do not yet support async fn or generic newtypes; they have no Kani (cfg(kani)) lowering yet.
  • No measurement of agent behaviour yet. Nothing here supports a claim that agents make fewer mistakes.

Dropped as not portable to Rust

Dropped as not portable to Rust: regions and arena brands, effect polymorphism, hidden-authority capture tracking in closures, staged macros, cleanup effects.
